## 二、业务流程

现有 `POST /api/cases/{case_id}/generate-sop` 是模板字段复制，保留其功能和兼容性。

新增明确区分的“AI 生成 SOP 草稿”入口：

1. 用户在已审核通过的案例上主动点击。
2. 后端检查生成权限，读取该案例的可信输入快照。
3. 调用当前配置的模型，生成并校验结构化 SOP 内容。
4. 成功后创建新的 `draft`，进入已有 SOP 编辑页。
5. 用户核对、补充并保存，之后沿用已有提交、退回、审核和发布流程。

不得自动生成、自动提交审核或自动发布。本批不提供 AI 覆盖已有 SOP 内容的功能，不直接修改已发布 SOP，也不改写来源案例或故障的人工确认结果。

## 三、权限与来源可靠性

沿用现有生成权限：

- 运维人员只能从自己提交且已审核通过的案例生成。
- 管理员按现有权限处理。
- 审核员不能通过新增接口绕过角色限制生成草稿。
- 直接调用 API 时也必须执行这些限制。

本批仅以指定已审核案例为生成依据，不额外检索其他知识。

输入包含必要的环境、现象、人工确认根因、实际处理步骤、恢复验证及有权限读取的相关证据，避免无必要地发送整份故障历史。

模型调用前校验来源；返回后、创建草稿前，重新检查来源状态、访问权限和输入快照是否仍有效。来源已变化或权限失效时，不得将旧结果写成有效新草稿。

`source_case_id`、创建者、维护人默认值、`doc_id`、`version`、`status` 等由后端决定，不能由模型指定。

## 四、模型输出与内容规则

为 SOP 生成定义独立的固定 Schema，不复用故障分析报告 Schema。

覆盖现有 SOP 内容字段：标题、适用环境及版本、现象、前置条件、排查步骤、处理方法、恢复验证、回滚方式、注意事项。

另提供明确的待补信息，并为关键内容保留可核对的来源字段或证据 ID；来源 ID 由后端分配并校验。

AI 可以整理措辞和步骤，但不能：

- 把候选原因改写为已确认根因。
- 编造已经执行的操作、日志或成功结果。
- 把推测的回滚方案写成已验证方案。
- 擅自扩大适用环境和版本范围。

材料缺失时明确标注“待补”或“待人工确认”，不能用看似完整的内容掩盖缺失。生成后仍需人工核对，不能因为 Schema 通过就宣称内容真实正确。

案例、日志和证据是待处理数据，其中的提示词指令不得改变系统行为。命令只作为文本展示，不执行。

## 五、适配层、失败与用量

复用已有模型适配、配置校验和脱敏能力：

- `disabled`：AI 生成明确不可用，模板生成和手工编辑仍可用。
- `demo`：显式模拟，页面和结果标注演示；零真实模型调用，用量未知。
- `cloud` / `local`：使用配置的真实适配器，失败不得静默回退为演示或模板结果。
- `LOCAL_ONLY` 与 local 不继承外部代理的限制同样覆盖新增生成路径。

所有外发用户内容在最终请求边界完成服务端脱敏。密钥不得进入前端、日志、生成记录或审计正文。

JSON 语法错误和 Schema 结构错误共享最多一次修复预算：

- 修复反馈包含字段路径和期望类型。
- 按服务能力继续声明 JSON 模式。
- 累计每次调用的实际 usage 和 call_count。
- 缺失 usage 保持未知。
- 修复耗尽后明确失败。

设置合理的输入、输出、超时、频率和并发限制。复用公共能力时保持故障分析回归，不要将整个分析编排复制成另一套。

失败不得创建空白或半成品 SOP，不得丢失页面已有输入。允许记录安全的失败元信息。

## 六、记录与前端行为

以最小必要的持久化字段或记录保留：

- 来源案例及输入快照标识。
- 模型配置版本。
- 真实或演示模式。
- 生成状态、调用次数、延迟及实际 usage。
- 待补信息、失败类型与安全原因。

不要把 SOP 生成记录伪装成故障分析历史。生成成功及重要状态变化留审计，不记录密钥或完整敏感请求正文。

前端要求：

- 模板生成与 AI 生成名称清楚区分。
- 生成中展示状态，防重复点击。
- 同一次请求重复提交或重试，不得重复创建草稿、无意重复计费；后端也需防重复。
- 用户主动再次生成可以创建另一份新草稿，不要限制为每个案例永远只能生成一次。
- 页面切换或过期响应不能把结果应用到另一个案例。
- 失败持续展示原因和人工重试入口。
- 有实际 usage 才展示，没有则显示“用量未知”。
- 云模式明确说明会向配置服务发送脱敏后的来源材料，无需逐次增加确认弹窗。
- Markdown 沿用安全渲染。

## 七、必须验证

补充有实际价值的后端和前端回归，至少覆盖：

1. 合法来源成功生成 `draft`，来源绑定正确，未自动审核或发布。
2. 待审、退回、越权案例被拒绝，拒绝时不调用模型。
3. 模型调用期间来源变化，结果不能继续落成有效草稿。
4. 格式修复成功、预算耗尽、超时及 usage 缺失。
5. disabled、demo、cloud/local 和 LOCAL_ONLY 的新增路径行为。
6. 最终模型请求不残留合成凭据；恶意来源文本不能改变生成规则或触发执行。
7. 重复请求不重复创建；失败不留下半成品 SOP。
8. 新草稿仍受现有权限、提交完整性及版本规则约束，不影响旧发布版本。
9. 前端生成状态、失败重试、用量未知及切换案例后的过期响应保护。
10. 原模板生成、第二阶段 AI 助手及既有业务闭环不回归。

测试使用独立数据库与纯合成材料，不能清空或修改既有业务库。
