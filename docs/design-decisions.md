# 设计决策

适用版本：3.7.1。本文记录产品范围、关键取舍和演进过程；实现细节见[架构](architecture.md)。

## 范围与规模

- 单组织、单实例、6–20 名内部用户、低并发，知识数据数百到数千条。
- 不做多租户、计费订阅、托管 SLA、SSO/LDAP、多活或公网 SaaS。
- 主流程：故障录入 → 补充证据 → 人工确认根因 → 案例审核 → SOP 发布 → 检索复用。

## 关键取舍

| 主题 | 选择 | 原因 |
|---|---|---|
| 架构 | 小型单体，前端 + 后端 + PostgreSQL | 规模小，部署与排障成本优先；不引入微服务、Redis、Celery、Elasticsearch |
| 部署 | 同一套 Docker Compose 覆盖 Windows 本地与 Linux 服务器 | 应用与模型位置解耦；运行不依赖 GPU |
| 模型接入 | 适配层，优先 OpenAI 兼容接口；`disabled` / `demo` / `cloud` / `local` | 不同服务对结构化输出、流式与 usage 支持不一致，能力开关显式配置 |
| 失败策略 | 模型或 embedding 失败明确报错并降级关键词检索，禁止回退云端 | 真实失败不能静默返回预设答案 |
| 数据外发 | `LOCAL_ONLY` 禁止云配置；云端模式明确告知脱敏后发送 | 应用级约束不等于网络隔离，边界需写清 |
| 知识边界 | 原始描述、AI 候选原因、人工确认根因、案例、SOP 分别存储 | AI 推测不能成为已确认事实 |
| 检索依据 | 只使用当前用户有权访问的已审核案例与有效已发布 SOP | 权限与状态在排序前和返回前各校验一次 |
| AI 输出 | 固定 JSON Schema，证据与引用 ID 由后端校验；允许证据不足 | 不编造案例、日志、处理结果或置信百分比 |
| 输入信任 | 日志与知识内容视为数据，不执行其中指令；不自动执行 AI 生成命令 | 防止提示词注入与越权操作 |
| 响应一致性 | 分析绑定故障 ID、输入版本和模型配置版本，丢弃过期响应 | 避免倒序响应覆盖新结果 |
| 权限 | 后端执行，前端只做展示 | 隐藏按钮不构成安全边界 |
| 演示模式 | 显式开启并逐条标注，业务接口与数据库仍为真实实现 | 演示与真实结果不得混淆 |

## 演进

- **v1.0**：登录与角色、故障录入、案例审核、SOP 版本、迁移与 Compose，无 AI 也能完成闭环。
- **v2.x**：生产加固——账号安全、登录限流、审计、备份与异地副本、维护任务韧性。
- **v3.0–3.6**：监控联动与只读诊断、AI 对话与只读工具、统一检索、通知与时间线、自助模型配置。
- **v3.7**：全站浅色信号光界面与动效统一。
- **v3.7+**：经典档案外观作为可选主题回归——只覆盖展示层（`html[data-theme]`），默认仍为信号光；主题选择保存在浏览器，不进入后端与权限判断。

## 非目标

自动处置或自动发布 SOP、多 Agent 编排、模型微调、托管云服务、多实例横向扩展。

需求与验收的完整历史见[版本记录](../CHANGELOG.md)；当前实现的验证范围见[质量与评测](evaluation.md)。
