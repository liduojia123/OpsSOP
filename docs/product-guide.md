# OpsSOP 产品使用指南

适用版本：2.0.0。

OpsSOP 将故障处理记录、人工确认的案例和可复用的 SOP 串成一条知识管理流程。运维人员负责处理和记录，审核人员负责确认知识质量，管理员负责账号、分类与运行配置。

## 角色与权限

| 操作 | 运维人员 `operator` | 审核人员 `reviewer` | 管理员 `admin` |
|---|---|---|---|
| 创建、编辑故障与追加检查记录 | 自己的故障 | — | 全部 |
| 查看故障详情 | 自己的故障 | 全部 | 全部 |
| 人工确认故障解决 | 自己的故障 | — | 全部 |
| 修改退回案例、重新提交 | 自己的案例 | — | 全部 |
| 审核案例 | — | 通过或退回 | 通过或退回 |
| 从已通过案例生成 SOP 草稿 | 自己提交的案例 | — | 全部 |
| 创建、编辑、提交 SOP | 自己的草稿或退回版本 | — | 全部可编辑版本 |
| 审核、发布、废弃 SOP | — | 支持 | 支持 |
| 阅读正式知识与提交 SOP 反馈 | 支持 | 支持 | 支持 |
| 管理账号、分类、向量索引 | — | — | 支持 |

权限由后端执行。未通过案例和未发布 SOP 对创建者、审核人员和管理员可见。已通过案例及已发布 SOP 对登录用户可读；SOP 历史和废弃版本可供追溯，但不进入正式诊断检索。账号由管理员创建，不提供公开注册。

## 处理一条故障

1. 登录后进入「故障」，创建记录，填写标题、现象、环境、服务、组件版本、近期变更、错误日志和已尝试措施。可以先保存草稿，再转为处理中。
2. 根据实际排查补充「检查结果」和「处理记录」。分类与标签可以人工填写，也可以核对 AI 建议后采纳。
3. 在右侧助手检索相关案例和 SOP。启用 AI 时可手动分析，也可在输入停顿后自动分析。建议命令只供阅读和复制，需由人员判断后在自己的运维环境执行。
4. 服务恢复后，填写实际根因、处理步骤和恢复验证，再执行「确认解决」。这三个字段均必填。
5. 系统将故障标为已解决，并生成待审核案例。已解决故障不能继续编辑或追加记录；AI 候选原因不会自动写入人工确认字段。

故障状态：`draft`（草稿）与 `open`（处理中）可以相互切换；「确认解决」后进入 `resolved`（已解决）。确认解决也可直接从草稿执行，只要人工确认内容完整。

## 审核案例

审核人员在「案例」中查看待审核内容，核对现象、环境、实际根因、处理过程和恢复依据：

- 通过：案例进入 `approved`，可作为正式检索和诊断依据。
- 退回：必须填写审核意见，案例进入 `returned`；创建者修订后重新提交为 `pending_review`。

案例在待审核状态保持内容快照，不能同时修改；已通过案例不可直接编辑。案例详情与原始故障分开呈现，查看正式案例不会自动开放来源故障的私有日志和完整历史。

编辑、提交或审核时如果记录已被他人修改，系统会拒绝旧操作并提示冲突。当前编辑内容保留在页面中；请先复制需要保留的内容，再刷新并核对最新记录。

## 编写和发布 SOP

可以手工新建 SOP，也可以在已通过案例中使用以下入口：

- **模板生成草稿**：将已确认的案例字段填入 SOP 模板，不调用模型。
- **AI 生成草稿**：使用当前模型整理指定案例，输出结构化草稿；缺失信息标为待补或待人工确认。

两种方式都创建草稿，需人工补充适用环境、现象、前置条件、排查步骤、处理方法、恢复验证、回滚和注意事项，再提交审核。排查步骤、处理方法和恢复验证不能为空。AI 生成不会修改来源案例，也不会自动提交或发布。

| 当前状态 | 操作 | 结果 |
|---|---|---|
| `draft` 草稿、`returned` 退回 | 创建者编辑并提交 | `submitted` 待审核 |
| `submitted` 待审核 | 审核通过 | `published` 已发布 |
| `submitted` 待审核 | 填写意见并退回 | `returned` 退回 |
| `published` 已发布、`superseded` 历史版本 | 派生新版本 | 创建新的 `draft` |
| 新版本待发布 | 审核通过 | 新版本发布，原发布版本转 `superseded` |
| `published` 已发布、`superseded` 历史版本 | 审核人员废弃 | `deprecated` 已废弃 |

已提交、已发布、历史和废弃版本不能直接编辑。同一份 SOP 只能保留一个未发布的新版本；新草稿审核期间，原发布版本继续有效。

通过 API 编辑、提交、审核或退回案例，以及编辑、提交、审核、退回、废弃 SOP 或派生新版本时，需先读取记录，将响应的 `updated_at` 原样放入请求头 `X-Expected-Updated-At`。缺少版本返回 428，版本过期返回 409；调用方应保留输入，读取最新内容后由用户决定如何处理。生成草稿和反馈接口不使用此前置条件。外部调用方升级时需要同步适配。

## 检索、引用与反馈

正式检索只使用已通过案例和当前有效已发布 SOP。未配置 embedding 或向量服务异常时仍可使用关键词检索，界面会显示检索方式及降级原因。AI 服务关闭不影响故障、审核、SOP 和关键词检索流程。

助手的「查看案例 / 查看 SOP」在新标签页打开对应来源，便于保留当前编辑内容。来源权限和版本由后端校验；历史版本直达页显示原版本及状态，不自动替换成新正文。

使用 SOP 后可反馈「有效」「无效」或「疑似过期」，并补充说明。反馈不会自动发布、换版或废弃 SOP，需由负责人评估后处理。

## 使用 AI 助手

助手将已知事实、候选原因、待补信息和下一步检查分开显示。候选原因是排查建议，最终根因由人员确认。信息不足时应继续补充证据。

自动分析默认在输入停顿约 2 秒后触发，可关闭；429 限流会暂停自动分析。故障切换、输入变化或请求倒序返回时，旧结果不会覆盖新内容。失败会显示原因，可人工重试；系统不静默切换为演示答案。

启用云模型时，脱敏后的问题、日志或知识片段会发送至管理员配置的服务。演示模式会明确标注模拟结果。模型配置与索引管理见 [AI 配置指南](ai-configuration.md)。

## 独立模拟环境

模拟内容用于培训和流程演示，需与正式数据分开。复制 `.env.example` 为 `.env.demo`，设置独立数据库名和口令，并调整：

```dotenv
OPSSOP_ENV=development
OPSSOP_SEED_DEMO=1
AI_MODE=demo
EMBEDDING_MODE=disabled
LOCAL_ONLY=1
BACKEND_PORT=18000
FRONTEND_PORT=18080
POSTGRES_PORT=15432
FRONTEND_HOST=127.0.0.1
```

同时设置演示运维与审核账号的 `OPSSOP_DEMO_OPERATOR_PASSWORD`、`OPSSOP_DEMO_REVIEWER_PASSWORD`，然后执行：

```text
docker compose -p opssop-demo --env-file .env.demo up --build -d
docker compose -p opssop-demo --env-file .env.demo exec -T backend python scripts/seed_demo_content.py
```

访问 `http://localhost:18080`，以 `operator`、`reviewer` 或管理员完成操作。初始化提供 OOMKilled、探针错误、端口不匹配、DNS、证书、Redis 及信息不足等合成场景。模拟分析明确标注演示，不代表真实模型效果；production 配置拒绝写入这些内容。

## 管理入口

管理员在「系统管理」维护账号、显示名、角色、启停状态、密码和分类；不能修改自己的管理员角色或停用自己的账号。账号列表支持搜索；审计记录支持按操作人、时间和事件筛选并分页。密码重置后该账号的既有会话立即失效。所有登录用户可以在侧栏修改自己的密码，修改后所有会话失效；退出登录会撤销当前会话。模型端点、密钥及模式通过后端环境变量配置；索引通过管理员 API 或运维命令构建。

登录及自行修改密码的验证尝试共用共享数据库限额：每个账号 60 秒内最多 10 次、每个直接连接来源最多 120 次，跨进程共享并在重启后保留窗口。达到限制时返回 429 和重试等待时间；失败会写入审计，不记录密码。容器 Nginx 对登录入口也有来源限流，反向代理后来源可能是代理地址，共享来源额度；公网部署应按[部署指南](deployment.md)在可信入口配置客户端地址与限流。

部署和日常维护参见 [部署指南](deployment.md)、[备份恢复](backup-restore.md) 与 [运维指南](operations.md)。
