# 站内通知与操作时间线

适用版本：3.6.1。

3.5.0 增加站内提醒：审核流转与监控告警不再只停留在列表里，当事人和审核人在顶部铃铛即可看到待办；故障、案例、SOP 详情页同时提供操作时间线，状态变化有据可查。

## 1. 通知事件

| 事件 | 触发动作 | 接收人 |
|---|---|---|
| `case.submitted` | 案例重新提交；或故障人工确认解决后生成/更新案例 | 启用的审核人员与管理员 |
| `case.approved` / `case.returned` | 案例通过 / 退回 | 案例创建者 |
| `case.sop_published` | 来源案例衍生的 SOP 发布 | 案例创建者 |
| `sop.submitted` | SOP 提交发布审核 | 启用的审核人员与管理员 |
| `sop.published` / `sop.returned` / `sop.deprecated` | SOP 发布 / 退回 / 废弃 | 创建者与维护人 |
| `fault.alert` | Prometheus 告警转故障 | 告警负责人与审核人员 |

规则：

- 通知只发给当事人与审核人，不广播给全部用户；正文只放标题、状态与审核意见摘要，不包含日志正文。
- 通知写入与业务变更在同一事务提交；业务失败不会留下孤立通知。
- 不看通知也能完成操作：通知只是提醒，权限与状态流转仍以业务接口为准。

## 2. 页面与接口

- 顶部铃铛：显示未读数量（最多显示 `99+`），每 60 秒刷新；切换页面时刷新。
- 点击条目：标记已读并跳转到对应详情；「全部已读」清空未读。
- `GET /api/notifications?unread_only=&limit=`：本人通知，倒序。
- `GET /api/notifications/unread-count`：本人未读数量。
- `POST /api/notifications/{id}/read`：标记本人通知已读；他人通知返回 404。
- `POST /api/notifications/read-all`：本人全部未读标记已读，返回更新条数。

保留策略：每日维护任务删除**已读且超过 90 天**的通知；未读通知始终保留，避免静默丢失提醒。

## 3. 操作时间线

`GET /api/audit/entity?entity_type=fault|case|sop&entity_id=<id>&limit=50` 返回该实体的审计动作（倒序），字段为动作、操作者显示名、详情与时间。

- 先校验实体是否存在以及当前用户是否可见：不存在返回 404，无权返回 403，不能通过时间线探测他人记录。
- 故障时间线包含：创建、更新、追加记录、人工确认解决、告警生成故障、衍生 SOP 发布回写。
- 案例时间线包含：更新、提交审核、通过、退回、衍生 SOP 发布回写。
- SOP 时间线包含：创建、更新、提交、发布、退回、废弃、派生新版本、使用反馈。
- 页面在故障/案例/SOP 详情右侧展示最近 20 条；完整审计仍由管理员在系统管理或 `/api/audit` 查看。

## 4. 与 SOP 发布回写的关系

SOP 发布时，如果 SOP 关联了来源案例：

1. 在案例时间线写入 `case.sop_published`；
2. 在来源故障时间线写入 `fault.sop_published`；
3. 通知案例创建者「衍生的 SOP 已发布」。

这样从故障出发可以追溯“最终沉淀成了哪份 SOP”，从 SOP 也能回到来源案例与故障。
